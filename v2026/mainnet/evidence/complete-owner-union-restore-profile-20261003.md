# Complete shared-owner restore profile

This source candidate adds an explicit `restore_coverage: "complete-union-v1"`
to each owner in a restore request. Absence retains the original single-owner
interpretation and JSON bytes. Fresh preparation rejects this field. A shared
restore must nominate every owner; an omitted owner is not a fresh namespace.

The core first obtains each fixed adapter's pure original census and requires
an exact disjoint union of all original files and custody attributes. Only the
old base preparation checkpoint is excluded from republication; its bytes stay
in the reviewed source inventory. Omitted, duplicated, invented or changed
members and heads refuse before owner payload staging. Apply repeats this
coverage check against the original pinned inventory before target mutation.

The first shared profile supports existing mainnet file-lock snapshots and the
local successor member census at the same root. Each view selects only its
actual fixed runtime namespace. A snapshot's pending temporary belongs to its
original checkpoint; unrelated or unknown names remain in the full source
inventory and must be covered by another known owner. Global nonce registries,
native journals, validator ledgers, fleet recovery and claim queues retain their
exclusive restore profiles. No generic directory or user-selected adapter is
introduced.

Local member census derivation changes only physical inode fields. The plan
retains both original and derived metadata digests, and publication transfers
the reviewed staging inodes with the existing no-replace protocol. Signed
payloads, nonces, approvals, pending payloads and capacities remain unchanged.
Independent snapshot heads are installed separately through the existing
write-ahead apply control; a joined exact-plan retry retains every already
acknowledged head rather than restarting the root.

The new deterministic controls exercise public plan/apply, all six co-owned
bootstrap/monitor/member readers, omitted and overlapping owners, unknown
retained files, and interrupted publication after one real head. Core controls
separately prove refusal before any owner staging. Test execution and published
dependency/current-server qualification are separate gates; compilation alone
does not qualify this behavior.

Remaining work includes actual successor execution rebind for a restored local
root, unfinished outer member-head restoration, retained in-place preparation,
and approved capacity/retention revisions. `restart_authorized` remains false;
this profile grants no signing, submission, service start or increased authority.
